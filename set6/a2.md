## Задача A2. Кратчайший блиц!

### Task 1

Модифицированный алгоритм Дейкстры для умножения:

```
vector<double> DijkstraMULT(const vector<vector<Edge>> &G, int start) {
  int n = G.size();
  const double INF = numeric_limits<double>::infinity();

  vector<double> dist(n, INF);
  vector<bool> visited(n, false);
  vector<int> path(n, 0);
  dist[start] = 1;

  using pii = pair<double, int>;
  priority_queue<pii, vector<pii>, greater<pii>> pq;
  pq.push({1.0, start});

  while (!pq.empty()) {
    auto [curProd, u] = pq.top();
    pq.pop();

    if (visited[u]) continue;

    visited[u] = true;

    for (const Edge &edge : G[u]) {
      int v = edge.end;
      double newProd = curProd * edge.weight;
      if (newProd < dist[v]) {
        dist[v] = newProd;
        pq.push({newProd, v});
        path[v] = u;
      }
    }
  }

  return dist;
}
```

Обычный алгоритм работает, когда нет циклов отрицательного веса. Да и вообще, когда нет отрицательных ребер, которые могут потенциально уменьшить путь.  

В модифицированном алгоритме Дейкстры роль таких ребер играют ребра с весом от 0 (включительно) до 1 (не включительно). Для них алгоритм работает некорректно.  
Плюс с этому в графе не должно быть отрицательных ребер, так как они вообще работают непредсказуемо: могут уменьшать путь, если он до этого был положительным, и увеличивать, если он до этого был отрицательным. Тут линейность точно нарушается! 

Итого: модифицированный алгоритм Дейкстры работает для графов с весами ребер в множестве [1; INF).

### Task 2

Реализация алгоритма восставновление списка смежности графа по матрице кратчейших путей: 

```
vector<vector<Neighbor>> RestoreGraph(const vector<vector<double>>& dist) {
  size_t n = dist.size();
  vector<vector<Neighbor>> G(n);

  for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
      bool flag = true;
      for (int k = 0; k < n; k++) {
        if (k == i || k == j)
          continue;
        if (dist[i][j] == dist[i][k] + dist[k][j]) {
          flag = false;
          break;
        }
      }
      if (flag) {
        G[i].push_back({j, dist[i][j]});
      }
    }
  }
  return G;
}
```

Рассмотрим ситуацию, когда граф определится неоднозначно.  
Рассмотрим два неориентированных графа - треугольник со сторонами 1, 1, 2 и такой же треугольник, у которого удалили сторону весом 2. 

Для обоих этих графов матрица кратчайших путей будет одинакова:  
0 1 1  
1 0 1  
1 1 0  

Итого: алгоритм однозначно не восстанавливает те графы, у которых между какими-то двумя вершинами есть два различных кратчайших пути (при условии, что наличие второго пути не повлияло на матрицу кратчайших путей).  

### Task 3

Ошибка состоит в том, что цикл по k находится не снаружи, а внутри. 

Рассмотрим ориентированный граф - квадрат со сторонами 1 (левая грань, стрелка вверх), 2 (верхняя грань, стрелка вправо), 3 (правая грань, стрелка вниз) и 10 (нижняя грань, стрелка влево).  
Матрица кратчайших путей:  
0   1   INF   INF  
INF 0   2     INF  
INF INF 0     3    
10  INF INF   INF  

Тогда на паре (3, 0) будет следующее: 

k = 0: dist[i][j] = 10, dist[i][k] = 10, dist[k][j] = 0.  
dist[i][j] = dist[i][k] + dist[k][j], поэтому dist[i][j] не меняется.  

k = 1: dist[i][j] = 10, dist[i][k] = INF, dist[k][j] = 1.  
dist[i][j] < dist[i][k] + dist[k][j], поэтому dist[i][j] не меняется.  

k = 2: dist[i][j] = 10, dist[i][k] = INF, dist[k][j] = INF.  
dist[i][j] = dist[i][k] + dist[k][j], поэтому dist[i][j] не меняется.  

k = 3: dist[i][j] = 10, dist[i][k] = 0, dist[k][j] = 10.  
dist[i][j] = dist[i][k] + dist[k][j], поэтому dist[i][j] не меняется.  

В итоге в dist[3][0] будет 10. И алгоритм больше не будет проверять пару (3, 0)!  
А на самом деле минимальное расстояние между 0 и 3 равно 1 + 2 + 3 = 6 (это путь по вершинам 0 - 1 - 2 - 3).
