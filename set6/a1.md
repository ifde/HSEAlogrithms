## Задача A1. Как построить минимальный остов?

### Алгоритм 1:    
Сортировка ребер по весу работает за `O(ElogE)` (это обычная сортировка массива)  
Для того чтобы получить список весь ребер, потребуется обойти граф - это `O(V + E)` (например, DFS). При условии, что структуру данных графа делаем в виде списка смежности (каждая вершина хранит информацию о соседях).  А если мы при добавлении ребер сразу сохраняем их в отдельный список, то это вообще O(1).  

Цикл foreach работает за `O(E)`.  
Удаление ребра `T - {e}` работает за O(v), если храним ребра в списках смежности.  

Далее, проверка графа на связность - это `O(V + E)` (используем DFS с подсчетом).  

В итоге получаем сложность AGL1: `O(ElogE) + O(V + E) + O(E) * (O(V) + O(V + E)) = O(ElogE) + O(E*V + E^2) = O(E * V + E^2)`.  

**Но это можно оптимизировать, если для проверки связности использовать DSU!**

Тогда на каждую проверку в цикле уйдет `O(E * alpha(V))`.  

Тогда общая сложность ALG1 получится: `O(ElogE) + O(V + E) + O(E) + O(E) * )O(V) + O(E * alpha(E))) = O(ElogE) + O(E^2 * alpha(E)) = O(E^2 * alpha(E))`  

В зависимости от количества вершин V в графе может быть более эффективным либо первый способ (с использованием DFS), либо второй способ (с использованием DSU).  

**Ответ: `O(E * V + E^2)` или `O(E^2 * alpha(E))`.**  

Ниже приведен пример реализации с помощью DFS:  

```
bool Graph::CheckConnection() {
  unordered_set<int> visited;
  DFS(adj.front().front(), visited);
  return visited.size() == V;
}

void Graph::removeEdge(int a, int b) {
  auto pos_a = find(adj[a].begin(), adj[a].end(), b);
  adj[a].erase(pos_a);
  auto pos_b = find(adj[b].begin(), adj[b].end(), a);
  adj[b].erase(pos_b);

  int weight;
  for (auto& edge : E) {
    if (edge.second.first == a && edge.second.second == b) {
      weight = edge.first;
      break;
    }
  }
  pair<int, pair<int, int>> pair = {weight, {a, b}};
  auto pos_c = find(E.begin(), E.end(), pair);
  E.erase(pos_c);
}

// Функция AGL1
vector<pair<int, pair<int, int>>> AGL1(Graph& graph) {
  vector<pair<int, pair<int, int>>> E = graph.E; // Получаем список рёбер
  sort(E.rbegin(), E.rend()); // сортировка по невозрастанию весов за O(ElogE)

  auto T = E;

  Graph new_graph(graph.V); // создаем новый граф, чтобы не удалять ребра из исходного
  new_graph.adj = graph.adj;
  new_graph.E = T;

  // Идем по всем ребрам за O(E)
  for (size_t e = 0; e < E.size(); e++) {
    int u = T[e].second.first;
    int v = T[e].second.second;

    new_graph.removeEdge(u, v); // удаляем ребро за O(v)

    // Проверка связности после удаления ребра {e} из T за O(V + E)
    if (new_graph.CheckConnection()) {
      T[e] = {-1, {-1, -1}}; // Если связан, то удаляем ребро из T
    } else {
      new_graph.addEdge(u, v, T[e].first); // иначе восстанавливаем ребро
    }
  }

  return T;
}
```

### ALG1 дает минимальное остовное дерево.

1) В конце работы алгоритма останется некоторое остовное дерево графа, так как циклов нет (если цикл есть, то алгоритм удалил бы какое-то ребро из него ранее - протироваречие).  
2) Далее, докажем, что полученный граф  содержит в себе минимальное остовное дерево исходного графа. По индукции.  
Это верно в начале алгоритма.
На k-м шаге все верно. Рассмотрим (k+1)-й шаг. Если мы не удалили ничего из минимального остовного дерева, то все ок.
Иначе пусть мы удалили ребро a из минимального остовного дерева и оно разбилось на два куска X и Y. Так как граф остался связным, то в нем есть ребро b от X до Y. Значит, до удаления ребра a был цикл a - X - b - Y - a. Значит, существует ребро c, которое не удалилось на до (k + 1)-го шага.
 
При этом, вес ребра b не может быть больше веса ребра a, так как иначе наш цикл удалил бы его перед a.  
Очевидно, меньше тоже не может быть, так как иначе исходное минимальное остовное дерево на самом деле не минимальное.  
Значит, веса ребер a и b равны и X - b - Y - тоже минимальное остовное дерево. 

Из этих двух утверждений следует, что в конце работы алгоритма у нас останется минимальное остовное дерево.  

Пример: пусть граф - это квадрат со сторонами весом 1, 1, 3, 3 и диагональю весом 5.  
Наш алгоритм удалит сначала диагональ весом 5, а затем сторону весом 3.  
В итоге мы и получим минимальное остовное дерево.  

### Алгоритм 2

Здесь можем применить DSU для эффективности! 

Цикл foreach - за `O(E)`.  
Добавление ребра в множество ребер и проверка на цикл - за `O(2alpha(V)) = O(alpha(V))`.  
В итоге получим сложность `O(E * alpha(V))`, что примерно равно `O(E)`.  

**Ответ: `O(E * alpha(V))`.**

Реализация алгоритма:  

```
struct Edge {
    int a;
    int b;
    int weight;
};

int DSU::find(int v) {
  if (parent[v] == v) return v;
  return parent[v] = find(parent[v]); // Сжатие пути
}

bool DSU::unite(int x, int y) {
  int rootX = find(x);
  int rootY = find(y);
  if (rootX == rootY) return false; // цикл найден
  if (rank[rootX] > rank[rootY]) swap(rootX, rootY);
  parent[rootX] = rootY;
  if (rank[rootX] == rank[rootY]) rank[rootY]++;
  return true;
}

vector<Edge> ALG2(int n, vector<Edge>& edges) {
  DSU dsu(n);
  vector<Edge> T;

  for (const Edge e : edges) { // цикл за O(e)
    if (dsu.unite(e.a, e.b)) { // Unite + проверка на цикл за O(alpha(V))
      T.push_back(e);
    }
  }

  return T;
}
```

### ALG1 не дает минимальное остовное дерево.  

Очевидно, что при произвольном проходе ребер и проверки на цикл мы в конце работы алгоритма получим остовное дерево, так как 
1. В полученном графе не будет циклов по условию алгоритма.
2. Полученный граф будет построен на всех ребрах. Докажем от противного: если не так, то есть минимум две компоненты связности и цикл бы в ходе работы нашел мост между ними и соединил - противоречие.
*Примечание: тут везде считаем, что исходный граф связный. А даже если не связный, то остовным деревом называем множество из объединения остовных деревьев для каждой компоненты связности.

Но цикл не гарантирует, что полученное остовное будет минимальным! 

Пример: граф - это квадрат со сторонами 1, 2, 3, 10.  
Минимальное остовное дерево имеет вес 1 + 2 + 3 = 6.  

А ALG2 может обойти ребра в порядке 10, 3, 2, 1.  
И получит вес остовного дерева 10 + 3 + 2 = 15.  

### Алгоритм 3

Цикл foreach - O(E)

Объединение T с ребром {e} - это `O(alpha(V))`, что приблизительно равно `O(1)`. Реализуем это через DSU.  

Далее проверка на цикл - это `O(alpha(V))` с использованием DSU.  
Поиск цикла - это `O(V + E)` через DFS.  
Поиск ребра с максимальным весом в цикле - это `O(V)`.   
Удаление ребра {e} из множества T - это `O(E)`.  

Получаем итоговую сложность: `O(E) * (O(2alpha(V)) + O(V + E) + O(V) + O(E)) = O(E) * O(V + E) = O(E^2 + E * V)`.

Ответ: `O(E^2 + E * V)`.  

Ниже приведена реализация ALG3:  

```
bool DSU::unite(int x, int y) {
  int rootX = find(x);
  int rootY = find(y);
  if (rootX == rootY) return false; // цикл найден
  if (rank[rootX] > rank[rootY]) swap(rootX, rootY);
  parent[rootX] = rootY;
  if (rank[rootX] == rank[rootY]) rank[rootY]++;
  return true;
}

// DFS, который ищет путь от current до target.
bool DFSUtil(vector<Edge>& T, int start, int finish,
             vector<int>& parent,
             vector<bool>& visited,
             vector<Edge>& path) {
  if (start == finish) {
    return true;
  }

  visited[start] = true;

  for (auto& edge : T) {
    int next = (edge.a == start) ? edge.b : (edge.b == start ? edge.a : -1);
    if (next == -1 || next == parent[start]) continue;
    if (next == finish) {
      path.push_back(edge);
      return true;
    }
    if (!visited[next]) {
      parent[next] = start;
      path.push_back(edge);
      if (DFSUtil(T, next, finish, parent, visited, path)) return true;
      path.pop_back();
    }
  }
  return false;
}

vector<Edge> findCycle(vector<Edge>& T,Edge e) {
  /* vector<Edge> T;
  for (auto& e : E) {
    Edge new_edge;
    new_edge.a = e.second.first;
    new_edge.b = e.second.second;
    new_edge.weight = e.first;
    T.push_back(new_edge);
  } */

  vector<int> parent(T.size(), -1);
  vector<bool> visited(T.size(), false);
  vector<Edge> path;
  path.push_back(e);

  DFSUtil(T, e.a, e.b, parent, visited, path);

  return path;
}

vector<Edge> ALG3(vector<Edge>& E, int V) {
  vector<Edge> T;
  DSU dsu(V);

  for (Edge& e : E) {
    T.push_back(e);

    if (!dsu.unite(e.a, e.b)) {
      vector<Edge> cycle = findCycle(T, e);
      if (!cycle.empty()) {
        auto to_delete = max_element(cycle.begin(), cycle.end(),
                                    [](Edge& a, Edge& b) { return a.weight < b.weight; });
        T.erase(remove_if(T.begin(), T.end(),
                          [&](Edge& edge) { return to_delete->a == edge.a && to_delete->b == edge.b; }),
                T.end());
      }
    }
  }

  return T;
}
```

### ALG3 дает минимальное остовное дерево!

1 - Полученный граф не будет содержать циклов по условию алгоритма.   
2 - Полученный граф будет связанным. Докажем от противного: если есть хотя бы две компоненты связности X и Y, то при попадании в множество T на i-й интеграции первого ребра, которое их соединяет, цикл бы точно не удалил это ребро.  

Алгоритм мог удалить это ребро, только про появлении цикла, то есть когда между этими компонентыми связности появилось бы другое ребро. 
Соответсвенно, на каждом этапе цикла начиная с i-й интеграции между X и Y всегда будет минимум одно ребро - противоречие. 

Значит, алгоритм выдает островное дерево. 

3 - Докажем, что алгоритм не удаляет те ребра из T, которые принадлежат минимальному основному дереву исходного графа. 
От противного: пусть мы удалили такое ребро e. 
В таком случае e было самым тяжелым ребром в некотором цикле c.
Пусть ребро e разбивает минимальное островное дерево на две компоненты связности X и Y. Тогда в цикле c есть ребро e’, которое является мостом между X и Y.  

А так как вес ребра e’ меньше веса ребра e, то суммарный вес дерева X-e’-Y меньше суммарного веса дерева X-e-Y - противоречие тому, что X-e-Y - минимальное основное дерево.  

Значит, на выходе алгоритма мы получим островное дерево, которое содержит все ребра минимального основного дерева - а это и означает, что мы получили минимальное основное дерево.  

Пример: пусть граф - это куб со сторонами 1, 1, 1, 1 и диагоналями 3, 3.  

Минимальное основное дерево - это три стороны общим весом 3.  

Теперь пусть алгоритм добавляет ребра в порядке 1 (левая сторона) - 1 (нижняя сторона) - 3 (главная диагональ) - 1 (верхняя сторона) - 1 (правая сторона) - 3 (побочная диагональ).  

Тогда: 
- На цикле 1 - 1 - 3 мы удалим ребро 3.  
- На цикле 1 - 1 - 1 - 1 мы удалим какую-то сторону (пусть правую).  
- На цикле 1 - 1 - 3 мы удалим ребро 3.  

В итоге получим минимальное остовное дерево.
